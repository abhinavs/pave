{# ================= 03 - BACKGROUND JOBS (SONIQ) ================= #}
03 Background jobs

Soniq: a job queue on the database you already have.

Soniq runs on Postgres. No Redis, no RabbitMQ, no extra box to babysit - the job table lives next to your application tables and ships with the same deploy. Enqueue from a route, return in milliseconds, let the worker do the slow part.

    {% for point in [ "Jobs take IDs, not ORM objects - they fetch their own data.", "Idempotent by convention: a missing row is not an error.", "Worker runs as its own systemd unit, restarted on every deploy.", "Watch it run live in the demo over SSE.", ] %}

app/jobs/generate_report.py 
async def generate_report(report_id: UUID, db: AsyncSession):
    report = await db.get(Report, report_id)
    if not report:
        return                  # idempotent, missing is fine

    report.status = "ready"
    await db.commit()


# enqueue from any route, then return right away:
await soniq.enqueue(generate_report, report_id=report.id)

tests/test_reports.py 
async def test_report_enqueues_job(authenticated_client, db_session):
    resp = await authenticated_client.post(
        "/api/reports", json={"range": "30d"})

    assert resp.status_code == 202
    assert resp.json() == {"status": "queued"}

    report = (await db_session.execute(
        select(Report))).scalar_one()
    assert report.status == "pending"

Tests you inherit, not ones you owe.

The suite ships with the template. pytest-asyncio in auto mode, an httpx client wired to the app, and a database session that rolls back after every test so cases never bleed into each other.

Then the suite earns its keep: fab validate runs ruff, strict mypy, the migration check, the env schema check and the full pytest run before a single byte reaches SSH. A green gate is the deploy. A red one never leaves your machine.
