# Your First Feature

You have Pave running. Now you want to add something of your own. This page walks through one real feature end to end, using the patterns the rest of the codebase already follows. By the end you will have:

- A new database table with a migration
- A JSON API: `POST /api/snippets`, `GET /api/snippets`
- An HTML page at `/snippets` listing what was saved
- Tests covering both surfaces

The feature is **Snippets**: a short title and body you can save and list. Trivial on purpose. The point is the pattern, which the same way scales to bookmarks, notes, posts, leads, jobs, anything CRUD-shaped.

---

## The four files that make a feature

Pave splits a feature into four files in four folders. Same split every time:

| File | What goes in it |
| --- | --- |
| `app/models/snippet.py` | The SQLAlchemy ORM model. The table definition. Nothing else. |
| `app/schemas/snippet.py` | Pydantic schemas for request input and response output. The ORM model never crosses an HTTP boundary. |
| `app/routers/snippets.py` | The route handlers. JSON and HTML both live here. |
| `templates/snippets/list.html` | The Jinja template the HTML route renders. |

Plus one migration generated by Alembic, and one line in `app/main.py` to register the router. That is the whole feature.

Why this split? The model layer and the wire layer change for different reasons. Pulling the wire shape into Pydantic means you can rename a column without breaking the API, return a subset of fields by default, and validate request bodies without writing validation by hand. `AGENTS.md` covers the reasoning in more depth; for now, the rule is: ORM models live in `app/models/`, DTOs live in `app/schemas/`, and routes only ever return DTOs.

## Step 1 - The model

Create `app/models/snippet.py`:

```python
import uuid
from datetime import datetime

from sqlalchemy import DateTime, String, Uuid, func
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class Snippet(Base):
    __tablename__ = "snippets"

    id: Mapped[uuid.UUID] = mapped_column(
        Uuid, primary_key=True, default=uuid.uuid4
    )
    title: Mapped[str] = mapped_column(String(200))
    body: Mapped[str] = mapped_column(String(4000))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )
```

Then register it so Alembic can see it. Open `app/models/__init__.py` and add:

```python
from app.models.snippet import Snippet  # noqa: F401
```

The `noqa: F401` is intentional. The import exists for its side effect (registering the model with `Base.metadata`), not for use in this file.

## Step 2 - The migration

Generate it:

```bash
pave migration --message "add snippets table"
```

Alembic prints the new file path. Open it and skim the `upgrade()` and `downgrade()` functions. You should see a `create_table("snippets", ...)` in `upgrade` and a matching `drop_table` in `downgrade`. If you do not see the downgrade, your model import in `__init__.py` is missing.

> **Always read the generated migration before applying it.** Alembic gets 95% of cases right and misses the same 5% every time (server defaults, JSON columns on SQLite, indexes on existing tables). Reading takes ten seconds.

Apply it:

```bash
pave migrate
```

**You should see:**

```
INFO  [alembic.runtime.migration] Running upgrade abc123 -> def456, add snippets table
```

## Step 3 - The schemas

Create `app/schemas/snippet.py`:

```python
import uuid
from datetime import datetime

from pydantic import BaseModel, Field


class SnippetCreate(BaseModel):
    """What the client sends."""
    title: str = Field(min_length=1, max_length=200)
    body: str = Field(min_length=1, max_length=4000)


class SnippetPublic(BaseModel):
    """What the server returns. Never the ORM model directly."""
    id: uuid.UUID
    title: str
    body: str
    created_at: datetime

    model_config = {"from_attributes": True}
```

Two schemas, always. One for input, one for output. `from_attributes = True` on the output schema lets `SnippetPublic.model_validate(orm_instance)` work without manual field copying.

## Step 4 - The router

Create `app/routers/snippets.py`:

```python
from fastapi import APIRouter, Depends, Request
from fastapi.responses import HTMLResponse
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from app.database import get_db
from app.models.snippet import Snippet
from app.schemas.snippet import SnippetCreate, SnippetPublic
from app.templating import templates

router = APIRouter(tags=["snippets"])


@router.post("/api/snippets", response_model=SnippetPublic, status_code=201)
async def create_snippet(
    data: SnippetCreate,
    db: AsyncSession = Depends(get_db),
) -> SnippetPublic:
    snippet = Snippet(title=data.title, body=data.body)
    db.add(snippet)
    await db.commit()
    await db.refresh(snippet)
    return SnippetPublic.model_validate(snippet)


@router.get("/api/snippets", response_model=list[SnippetPublic])
async def list_snippets(
    db: AsyncSession = Depends(get_db),
) -> list[SnippetPublic]:
    result = await db.execute(
        select(Snippet).order_by(Snippet.created_at.desc()).limit(100)
    )
    return [SnippetPublic.model_validate(s) for s in result.scalars()]


@router.get("/snippets", response_class=HTMLResponse)
async def snippets_page(
    request: Request,
    db: AsyncSession = Depends(get_db),
) -> HTMLResponse:
    result = await db.execute(
        select(Snippet).order_by(Snippet.created_at.desc()).limit(100)
    )
    return templates.TemplateResponse(
        request, "snippets/list.html", {"snippets": list(result.scalars())}
    )
```

Three routes, two surfaces. `/api/snippets` returns JSON (validated against `SnippetPublic`). `/snippets` renders an HTML page using the same data. Same database query, two presentations.

## Step 5 - The template

Create `templates/snippets/list.html`:

```html
{% extends "_base.html" %}

{% block title %}Snippets{% endblock %}

{% block content %}
<section class="container py-8">
  <h1 class="text-2xl font-semibold mb-6">Snippets</h1>

  {% if snippets %}
    <ul class="space-y-4">
      {% for s in snippets %}
        <li class="card">
          <h2 class="font-medium">{{ s.title }}</h2>
          <p class="text-sm text-[--text-muted] mt-1">{{ s.body }}</p>
          <p class="text-xs text-[--text-subtle] mt-2">{{ s.created_at.strftime("%Y-%m-%d %H:%M") }}</p>
        </li>
      {% endfor %}
    </ul>
  {% else %}
    <p class="text-[--text-muted]">No snippets yet. POST one to /api/snippets to see it here.</p>
  {% endif %}
</section>
{% endblock %}
```

`_base.html` provides the page chrome (nav, footer, the styled body container). Pave's design system gives you `card`, layout helpers, and CSS variable tokens; see [components.md](components.md) for the full set.

---

## Step 6 - Wire it up

Open `app/main.py` and register the router. Find the block that imports other routers (look for `from app.routers import ...`) and add yours:

```python
from app.routers import snippets

# Later in the file, where other routers are included:
app.include_router(snippets.router)
```

Save. `pave dev` reloads automatically.

## Try it

In one terminal:

```bash
pave dev
```

In another, create a snippet via the JSON API:

```bash
curl -X POST http://127.0.0.1:8000/api/snippets \
  -H "Content-Type: application/json" \
  -d '{"title":"First","body":"It works."}'
```

**You should see:**

```json
{
  "id": "1f2e...",
  "title": "First",
  "body": "It works.",
  "created_at": "2026-05-27T18:42:11.412Z"
}
```

Open http://127.0.0.1:8000/snippets in your browser. Your snippet is there.

If `DEBUG=true`, http://127.0.0.1:8000/api/docs shows the new endpoints, schemas, and an interactive "Try it out" button. That page is regenerated from the schemas; you did not write a line of OpenAPI by hand.

## Test it

Create `tests/functional/test_snippets.py`:

```python
async def test_create_and_list_snippet(async_client):
    create = await async_client.post(
        "/api/snippets",
        json={"title": "Hello", "body": "World"},
    )
    assert create.status_code == 201
    created = create.json()
    assert created["title"] == "Hello"

    listing = await async_client.get("/api/snippets")
    assert listing.status_code == 200
    titles = [s["title"] for s in listing.json()]
    assert "Hello" in titles


async def test_create_snippet_rejects_empty_title(async_client):
    response = await async_client.post(
        "/api/snippets",
        json={"title": "", "body": "x"},
    )
    assert response.status_code == 422
```

Run them:

```bash
pave test
```

`pytest-asyncio` runs in auto mode, so the `async def test_...` functions need no decorator. The `async_client` fixture (in `conftest.py`) spins up the app against a transactional test database; each test rolls back at the end.

## What you just learned

You added a feature using every Pave pattern:

- Model in `app/models/`, registered in `__init__.py`
- Generated and reviewed an Alembic migration
- Input and output schemas in `app/schemas/`
- Routes returning DTOs, never ORM objects
- Two surfaces (JSON + HTML) over the same query
- Tests against the real database

Every other feature you build will use the same shape.

## What to build next

Pick the next page based on what your real feature needs.

- **Make the list live-update with HTMX** (a partial route, no full page reload) -> [components.md](components.md). The webhook demo at `/webhooks` is the reference implementation.
- **Run slow work off the request path** (sending email, calling third-party APIs, processing uploads) -> [background-jobs.md](background-jobs.md).
- **Restrict the route to signed-in users** -> add `user: User = Depends(require_verified_user)` and read [auth.md](auth.md).
- **Ship it to your server** -> `fab production deploy`. The migration runs on the server before the symlink flips, so the new table is in place before the new code that uses it.
